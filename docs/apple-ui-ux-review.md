# Apple UI/UX and release readiness review

Reviewed 26–27 September 2026 against MVP checkpoint `b147ec4`, the subsequent fixes, and current official Apple documentation. This is a source and simulator review, not an Apple certification or a guarantee of App Review approval. Notifications remain out of scope.

## Assessment

The MVP has a sound native foundation: SwiftUI navigation, lists, forms, sheets, confirmation dialogs, semantic text styles, SF Symbols, selectable conversation text, explicit offline/error states, and preserved drafts during connection failures. Agent states have text and symbols as well as color. Chat auto-scroll respects Reduce Motion. Credentials use the Keychain. These choices should remain the baseline.

The review found small inline controls, text contrast problems, and crowded horizontal layouts at accessibility text sizes. The fixes address these with larger label hit regions, a persistent composer label, adaptive text and message colors, and layouts that reflow at accessibility sizes. Distribution preparation is incomplete. HIG recommendations and submission requirements are distinguished below.

Apple recommends [44 pt button hit regions](https://developer.apple.com/design/human-interface-guidelines/buttons), [reflowing content at larger text sizes](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/larger-text-evaluation-criteria), and checking [sufficient contrast in both appearances](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/sufficient-contrast-evaluation-criteria). These are accessibility and interaction criteria; a source review alone does not establish that every screen meets them.

The fixes retain native navigation and controls. Permission actions, agent rows, tool headers, and new-thread setup reflow; compact context usage becomes readable text at accessibility sizes. Diff rows retain their +/− markers and tinted backgrounds while using readable text. Empty thread guidance reflects host capability, and draft wording explicitly describes session-only retention. Review caught and corrected a temporary loss of attention-reason text during row refactoring. Audit findings prompted darker adaptive supporting text (`Color.primary.opacity(0.75)`), readable status/error words, and separate colored status icons. These changes preserve the hierarchy and meaning without depending on color alone.

Simulator evidence also exposed a native-control problem: at AX5 on iOS 27, the permission confirmation dialog became a narrow, excessively wrapped popup with no visible Cancel action. The confirmation now uses a native alert with the same request title, details, choice, and explicit Cancel action. Source inspection confirms the host permission response still occurs only after confirmation. Connection setup now supplies a native keyboard Done action and interactive scroll dismissal, making the URL keyboard easy to dismiss before reviewing the form. The dark appearance test hook is restricted to debug builds.

**Agent-control follow-up, 27 September 2026:** The new three-choice active-send/recovery native alert also clipped Cancel at AX5. It was changed to a native scrollable sheet with a visible toolbar Cancel; Stop and permission confirmation remain native two-action alerts. The composer now limits itself to two visible lines at accessibility text sizes and dismisses the keyboard before opening the active-send sheet, leaving its actions reachable on a narrow phone. Two focused AX5 simulator tests passed for these control/recovery paths (`.build/agent-control-ax-sheet-r4.xcresult`). Subsequent fixes made contrast, receipt selectors, and the demo host identity accurate; a final native audit verified the prominent Stop label using system background and text colors (`.build/agent-control-audit-prominent.xcresult`). Across the focused, regression, functional-rerun, and audit result bundles, **20 distinct UI tests passed** (`.build/agent-control-ui-regression.xcresult`, `.build/agent-control-ui-final.xcresult`). The initial broad run's five failing tests were corrected and rerun; no accessibility audit checks were suppressed. The updated unit suite passed 91 tests and the final Release simulator build passed (`.build/agent-control-release-final-r3.log`). This follows the original MVP review and does not change its historical 77-unit/14-UI validation record below.

At the review checkpoint, an informational Privacy & Host Data sheet was available from connection setup and the workspace menu. The 27 September 2026 UI refinement removed that sheet and its entry points. The app still needs an owner-approved public privacy policy, support contact, and a decision about third-party AI sharing before distribution; the former factual sheet did not satisfy those requirements.

An original AppIcon asset was added separately in commit `e252774` after the initial review; the missing-icon row above records the earlier checkpoint. Its rendered appearances and a signed distribution archive have not been validated by this review.

No app account creation or social login was found, so this review does not request an unrelated account-deletion flow or Sign in with Apple. The iPhone-only product decision remains intact.

## Validation record and limits

- Baseline lint passed, and the parent run reports 77 unit tests passing on iPhone 17 / iOS 27.
- Baseline screenshots were visually inspected for setup, projects, chat, and AX5 usage. Default layouts are orderly; the checkpoint's compact context gauge moved on 27 September 2026 into a compact accessory row above the composer, with an icon and percentage at accessibility text sizes. The provider/model row also needed the accessibility-size treatment now implemented.
- Focused native accessibility audit passed on iPhone 17 / iOS 27: 1 test, 0 failures, 34.922 seconds (`.build/review-accessibility-v5.xcresult`). Earlier measured failures drove the supporting-text corrections, readable Connect action, keyboard dismissal, and removal of a tiny decorative chat separator.
- The AX5 dark interaction test passed on iPhone 17 / iOS 27 in 62.952 seconds (`.build/review-accessibility-v4.xcresult`). It enforces dark appearance, verifies full permission-control bounds above the composer, opens Allow confirmation and cancels, checks context usage, and sends a message with the keyboard visible. Reviewed screenshots confirm a readable native alert with both Allow and Cancel visible and a composer/send control that fits above the keyboard.
- The audit has no suppression handler or disabled-control exclusion. It fills the endpoint, verifies Connect is enabled, and dismisses the keyboard before auditing the form. Automated contrast, hit-region, element-detection, description, and trait audits cover setup, projects, and the running chat only. The AX5 dark flow covers permission controls/confirmation, context usage, and composing/sending. It does not establish contrast compliance on every screen or every state.
- The full run on the narrower iPhone 17e / iOS 27 passed all 77 unit tests and 13 of 14 UI tests (`.build/review-final.xcresult`), including both new accessibility tests. The existing AX5 usage test stopped in its old connection helper before reaching usage; video confirmed the keyboard remained visible after the reported Done tap.
- A test-only synchronization correction waits until Done is hittable, taps it, and waits for the keyboard to disappear before continuing. The focused rerun passed all 4 selected tests with 0 failures in 86.860 seconds: AX5 usage, ordinary connect/send, connection failure, and empty state (`.build/review-final-followup.xcresult`). All 77 unit tests and all 14 distinct UI tests have passing coverage across these runs. The original full-run bundle retains its failure; a new all-in-one 91-test run was not performed after the helper correction.
- The final Release simulator build passed (`.build/review-release-final-verified.log`). No application code changed after that build; the subsequent edit was confined to the existing UI-test helper.
- Final Release bundle inspection verified the privacy manifest, `UILaunchScreen`, version `0.1.0` / build `1`, iPhone-only device family, and declared minimum OS `17.0`.
- The source review checked all feature views, connection storage, app startup, and project configuration. The iOS 17 minimum runtime, landscape orientation, Increase Contrast, physical-device VoiceOver gestures, local-network denial, real-host connections, and signed distribution archive/upload were not exercised in this review.
- Before public distribution, finish physical-device and manual VoiceOver coverage, including error/offline states and expanded tools. Automated auditing complements a manual VoiceOver pass; it does not replace it.

Source/policy review and upstream Paseo research were delegated independently from implementation. Separate implementation work covered UI fixes, project/privacy configuration, and accessibility tests; the coordinating agent reviewed integration, ran builds/tests, and inspected evidence. Review feedback preserved agent attention details and strengthened tests after screenshots exposed coverage gaps. The result retains native controls and the existing protocol boundary. Owner-dependent release items remain explicitly unresolved.
